# PRD: 오늘

> **한 줄 요약:** 매일 반복되는 내 일과를 텍스트로 적고, 끝낸 항목은 V 체크. 자정에 체크가 리셋되고 새 하루 시작. 그게 전부. **웹에서 동작 (Next.js + FastAPI + Supabase, n=1).**

## 1. 배경 (Background)

기존 투두 앱(Todoist, TickTick 등)은 반복 설정·태그·우선순위가 많아 매일 반복 루틴에 비해 무겁고, 영양제 알람 앱은 영양제만 다룬다. 사용자 본인(seunwoo)이 여러 앱을 시도했지만 무거워서 결국 안 쓰게 된 경험이 반복됨. **반복되는 일과 전반**을 가장 단순한 형태(텍스트 + V 체크)로 다루는 1인용 도구가 필요. n=1 개인 사용 + BMad 튜토리얼 한 사이클 실습 대상이며, **이번 실습의 학습 대상 스택은 Next.js + FastAPI + Supabase**.

상세 배경·페르소나·경쟁 분석은 `_bmad-output/planning-artifacts/briefs/brief-bmad-tutorial-2026-05-18/brief.md` 참조. *(브리프의 플랫폼/저장/개발 방식 행은 2026-05-19 갱신본 기준으로 본 PRD와 동기화되어 있음.)*

## 2. 목표 및 성공 신호 (Goals & Success Signals)

외부 KPI는 의미 없음. 개인 기준 성공 신호:

- **G1.** 매일 한 번 이상 앱을 연다 — 1개월 평균 주 6일 이상
- **G2.** 등록한 항목의 80% 이상을 평균적으로 체크한다 — 등록만 해두는 게 아님
- **G3.** 등록 항목이 10개를 넘지 않는다 — 단순함이 유지되고 있다는 신호
- **G4.** 새 기능을 추가하고 싶은 욕구가 생기지 않는다 — "충분하다"의 증거
- **G5.** BMad 워크플로우 한 사이클을 완주한다 (브리프 → PRD → 아키텍처 → 구현 → 회고)

**Counter-metrics (반대 신호):** 항목이 매일 늘어난다 / 체크 후 V를 다시 해제하는 빈도가 높다 / 알림이 그리워진다 → 단순함을 잃고 있다는 경고.

## 3. 사용자 (User)

**Primary user: seunwoo 본인 — n=1**

- 30대, 매일 챙겨야 할 작은 일과 보유 (영양제·운동·물·독서·명상 등)
- 기존 투두/영양제 앱이 무거워서 포기한 경험
- 단순함을 가장 큰 가치로 여김

페르소나 일반화 없음. 본인이 매일 안 쓰면 실패.

## 5. 기능 요구사항 (Functional Requirements)

### F1 — 일과 항목 관리 (CRUD)

- **FR1.1** 사용자는 새 일과 항목을 **텍스트 한 줄**로 추가할 수 있다.
- **FR1.2** 사용자는 기존 항목의 텍스트를 수정할 수 있다.
- **FR1.3** 사용자는 항목을 삭제할 수 있다. 삭제 시 별도 확인 단계 없음. [ASSUMPTION] *단순함 우선 — 실수 삭제 시 다시 적으면 되는 정도의 비용으로 가정.*
- **FR1.4** 사용자는 항목의 표시 **순서를 변경**할 수 있다 (예: 드래그 정렬). [ASSUMPTION] *드래그 방식이 가장 단순. 다른 방식 선호 시 UX 단계에서 결정.*
- **FR1.5** 항목 텍스트 길이 상한: **60자**. [ASSUMPTION] *"한 줄"이라는 컨셉 유지를 위한 가드레일. 실사용에서 짧음.*

### F2 — V 체크 토글

- **FR2.1** 사용자가 항목을 **탭하면 V 체크가 표시**된다.
- **FR2.2** 체크된 항목을 다시 탭하면 **체크가 해제**된다.
- **FR2.3** 체크 상태 변경은 즉시 시각적으로 반영된다 (별도 저장 버튼 없음).
- **FR2.4** 체크된 항목은 시각적으로 구분되되 **목록에서 사라지거나 순서가 바뀌지 않는다**. [ASSUMPTION] *"끝낸 것도 자기 자리에 그대로" — 같은 자리에서 흐름을 볼 수 있어야 함.*

### F3 — 일일 자동 리셋

- **FR3.1** **자정 (00:00 클라이언트 로컬 시간)** 에 모든 항목의 V 체크가 자동 해제된다. 항목 목록 자체는 유지된다. [ASSUMPTION] *브리프의 "자정 또는 사용자 정의 기상 시간" 중 단순함 우선으로 자정 고정. n=1 단일 사용자이므로 서버 시간이 아닌 클라이언트 로컬 시간 기준. 추후 V2에서 사용자 정의 옵션 검토.*
- **FR3.2** 탭을 닫았거나 세션이 만료된 상태여도 다시 접속하면 **마지막 동기화 시점과 현재 시점 사이의 자정 경과를 감지해 리셋 적용**한다 (예: 자정을 지난 시점에 페이지를 다시 열면 자동 해제 반영).
- **FR3.3** 리셋 직전 체크 상태는 별도 저장·이력화되지 않는다. (이력 기능 V1 미포함)

### F4 — 오늘 화면 (Today)

- **FR4.1** 서비스 URL 접속 시 가장 먼저 **오늘 화면(Today)** 이 표시된다. (별도 로그인/스플래시 단계 없음 — 인증 미사용)
- **FR4.2** 오늘 화면은 등록된 항목 전체와 각 항목의 체크 상태를 한 화면에 보여준다.
- **FR4.3** 오늘 화면에서 직접 항목을 **추가/체크/순서 변경**할 수 있다 (별도 화면 이동 없이). [ASSUMPTION] *수정·삭제는 항목별 액션(데스크톱: hover 액션 / 모바일: 롱탭·스와이프 등)으로 진입 — UX 단계에서 결정.*
- **FR4.4** 빈 상태(항목 0개)에서는 **"첫 항목을 추가해보세요"** 류의 단순한 안내가 표시된다. [ASSUMPTION] *온보딩·튜토리얼 없음 — 빈 상태 메시지로 충분.*

## 6. 비기능 요구사항 (Non-Functional Requirements)

- **NFR1 (스택).** 프론트엔드 **Next.js**, 백엔드 **FastAPI**, 데이터베이스 **Supabase (Postgres)**. n=1 / 인증 없음. Supabase Auth/RLS 미사용 — FastAPI 서버에서 service-role 키로 Postgres에 접근하고, Next.js는 FastAPI를 통해서만 데이터에 도달한다. [ASSUMPTION] *Supabase가 REST/Auth를 제공함에도 FastAPI를 중간에 두는 이유는 BMad 튜토리얼 실습 목적. 정당화는 아키텍처 문서에서.*
- **NFR2 (영속성).** 모든 항목과 체크 상태는 Supabase에 저장된다. 브라우저 캐시·세션 종료·기기 변경 후에도 같은 URL로 접속하면 동일한 데이터가 보인다.
- **NFR3 (응답 속도).** 페이지 로드 후 **1초 이내**에 오늘 화면이 인터랙션 가능한 상태로 표시된다. 체크/추가 같은 사용자 액션은 네트워크 RTT 포함 **300ms 이내**에 시각적으로 반영된다. [ASSUMPTION] *낙관적 UI 미적용. RTT가 큰 환경에서 NFR3 만족이 어려울 수 있어 아키텍처 단계에서 측정 후 재조정.*
- **NFR4 (단순성).** 오늘 화면 외 진입 가능한 별도 페이지/라우트 수는 최소화한다. 메뉴/설정/탭 네비게이션 지양. [ASSUMPTION] *설정 페이지가 필요하면 가장 얇게 — 예: 데이터 초기화 한 가지 정도.*
- **NFR5 (플랫폼).** **반응형 웹** — 데스크톱과 모바일 브라우저 모두에서 동작. 별도 PWA/네이티브 앱 빌드 없음. 주 브라우저는 최신 Chrome 계열로 가정. [ASSUMPTION] *iOS Safari·Galaxy 기본 브라우저 동작 검증 범위는 아키텍처 단계에서 결정.*
- **NFR6 (온라인 전제).** 앱은 네트워크 연결을 전제로 동작한다. 오프라인 상태에서는 사용자에게 명확한 상태 표시(예: "연결 없음")를 제공하되 별도 큐잉/복구 로직은 없다.

## 7. 사용자 여정 (User Journey)

n=1 단일 사용자 + 매우 얇은 인터랙션이라 하루 한 사이클만 캡처.

**UJ-1: 아침 → 낮 → 저녁 한 사이클**

1. **아침:** 일어나서 브라우저로 "오늘" URL을 연다(데스크톱은 북마크, 모바일은 홈 화면 바로가기 가정) → 자정 리셋으로 모든 V가 해제된 깨끗한 목록을 봄.
2. **낮 동안:** 영양제를 먹은 직후, 운동을 마친 직후 같은 시점에 페이지를 열어 해당 항목을 탭/클릭 → V 체크.
3. **저녁:** 자기 전 한 번 더 열어 남은 항목 처리. 못 한 항목은 그대로 두고 잠.
4. **자정 이후:** (탭 닫힌 상태) 자정이 지나면, 다음에 페이지를 열 때 클라이언트 시계 기준 자정 경과를 감지해 체크가 자동 해제된 상태로 로드. 다음 날 아침 다시 1번부터.

(이력 화면이 없으므로 "어제 뭐 했는지 다시 보기"는 V1 범위 밖.)
